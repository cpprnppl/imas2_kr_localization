# iM@S2 360 실기 한글 패치 (데이터판)

원본 360 ISO에서 **한글 게임 데이터·폰트를 넣은 새 ISO**를 만든다. 원본 ISO는 읽기만 한다.

## 전제 (가정)
- **실기 = RGH/JTAG 개조 360**으로 가정한다. 이 PC에서는 실기 시험을 할 수 없고, 실기 확인은 사용자가 한다.
- 디스크 데이터 파일은 서명 대상이 아니다. `Default.xex`는 **원본 그대로** 둔다(복호화·재서명 없음).
- 출력 형식은 XISO(게임 파티션만)다. iM@S1 360 패처(아래 출처)가 만드는 형식과 같다.

## 이번 판에 들어가지 않는 것 (사용자 결정 대기)
- **실행 파일(xex) 안의 문자열**(화자 이름표, 일시정지 메뉴, 스케줄·지역명 등)은 **일본어로 남는다.**
  - PC 포트에서는 실행 중에 패치한다(`kor_exe_strings.bin`). 실기용으로 xex에 고정하려면 xex를 복호화하고 서명 없이 다시 써야 한다. 그 처리 방식을 사용자가 결정하기 전까지 보류한다.
- **한글 DLC**(카탈로그 페이지, 곡 가사): 실기용 DLC 패키지(STFS)를 다시 만들어야 하므로 같은 이유로 보류한다. DLC는 원본을 그대로 쓰면 일본어로 나온다.
- **Vol.08 메인 메뉴 배너의 한글 로고**: PC 포트 전용 형식(IM2PCRAW)이라 실기에서는 쓸 수 없다. 원본 그림 그대로 나온다.

## 만드는 법 (이 PC)
```bash
python -I tools/x360_patch/build_iso.py "C:\Users\jackfilm\Desktop\imas2_360\Idolmaster 2, The (Japan).iso" "C:\Users\jackfilm\Desktop\imas2pc\game_kor" "C:\Users\jackfilm\Desktop\imas2_360_kor\Idolmaster 2, The (Japan) [KOR].iso"
```
- 원본 ISO의 파일 목록(3,136개)을 그대로 쓰고, 내용은 `game_kor`에서 가져온다. `game_kor`에만 있는 PC 포트 전용 파일·백업(`kor_exe_strings*`, `_backup*`, `_kor_backup`, `.orig_kor`)은 넣지 않는다.
- 다른 세션이 `game_kor`에 배포하는 중일 수 있어서, 먼저 `<출력>.stage\`로 사본을 뜬 뒤 그 사본으로 만든다.
- **검증**: 새 ISO에서 파일을 전부 다시 읽어 사본과 sha1을 비교한다(불일치 0이어야 종료 코드 0). 원본 ISO의 sha1은 전후로 비교한다.
  - 결과는 `<출력>.manifest.json`에 남는다: 파일별 sha1·출처, 원본 sha1 전/후, 출력 sha1.
- 무거운 작업이므로 GPU 측정 런이 `gpu_run.lock`을 쥐고 있을 때는 돌리지 않는다.

## 테스터 안내 (실기 시험)

### 받는 것
- `Idolmaster 2, The (Japan) [KOR].iso` (XISO, 게임 파티션만). 받은 뒤 sha1을 확인한다. 값은 같이 받는 `.manifest.json`의 `out_sha1`이다.

### 준비
- RGH/JTAG 개조 360. 순정 기기와 순정 디스크로는 실행할 수 없다.
- 일본판 「アイドルマスター２」 원본에서 만든 ISO여야 한다. 다른 판(플래티넘판 등)은 확인하지 않았다.

### 넣는 법
1. `[KOR].iso`를 평소 쓰는 방식으로 올린다.
   - ISO→GOD 변환 도구(각자 가진 것)로 GOD로 바꿔 HDD `Content\0000000000000000\4E4D0817\00007000\`에 넣는다.
   - 또는 ISO 내용을 풀어 HDD 폴더에 두고 런처에서 `default.xex`를 실행한다.
2. 세이브는 원본과 같은 실행 파일이 쓰므로 형식이 같을 것으로 본다. **확인되지 않았으므로 기존 세이브는 먼저 백업**한다.
3. 되돌리기: 원본 ISO(또는 원본 디스크)로 실행한다.

### 이 판에서 정상인 것 (일본어로 남는 곳)
- 실행 파일 안의 문자열: 화자 이름표, 일시정지 메뉴, 스케줄·지역명 등.
- 다운로드 콘텐츠(DLC) 전부: 카탈로그 페이지, 곡 가사.
- 메인 메뉴 Vol.08 배너 로고.
- 곡 제목 로고와 재킷: 팀 규칙에 따라 원문 유지.

### 확인할 것 (보고 양식)
- 부팅 → 타이틀(한글 「아이돌마스터」 그림) → 메인 메뉴까지 가는지.
- 프로듀스 시작 → 첫 대화(미키 프롤로그)가 한글로 나오는지, 글자가 빈칸(□)·깨짐 없이 나오는지.
- 레슨·오디션·라이브 한 번씩: 멈춤, 검은 화면, 소리 끊김이 있는지.
- 문제가 있으면 다음을 적어 보낸다:
  - 화면 사진
  - 직전에 한 조작
  - 세이브 시점
  - 화면 속 일본어 원문(있으면)

### 이 PC에서 확인한 것 / 못 한 것
- 확인: 새 ISO에서 3,136개 파일을 다시 읽으면, 만들 때 뜬 한글판 사본(`game_kor` 스냅샷)과 sha1이 전부 일치함. 원본 ISO의 해시는 전후로 같음(변경 없음).
- Xenia(에뮬레이터): 타이틀 화면까지 나오고 한글 타이틀 그림이 보임. 그 뒤는 원본 ISO도 똑같이 흰 화면이 되어 이 PC의 Xenia로는 더 확인할 수 없었음.
- 실기: 확인하지 않음 → 테스터 보고로 확인한다.

## 파일
- `xdvdfs.py`: XDVDFS 읽기(목록/풀기). XGD1/2/3과 XISO의 파티션 위치를 자동으로 찾는다.
- `xiso_write.py`: XISO 쓰기. 디렉터리 항목은 대문자 이름 순 이진 트리로 만들고, 항목이 섹터 경계를 넘지 않게 한다. 속성값은 원본과 같다(파일 0x80, 폴더 0x90).
- `build_iso.py`: 위 두 개로 한글 ISO를 만들고 검증한다.

## PC 포트 최종 패치 데이터 (gen_patch.py, 배포 전 · 빌드만)
- `gen_patch.py`: 사용자 원본 360 파일에 대한 KDF1 diff(`kd.py`) + 우리 파일 통째(`retry_text.bin`, `difficulty_text.bin`, `kor_exe_strings.bin` KXS2) + `manifest.json`.
  - 디스크 항목은 원본 ISO 파일 목록에서, DLC는 원본 패키지 파일 목록에서만 만든다(game_kor·content_kor 폴더를 훑지 않음 → 백업 파일이 섞이지 않음).
  - 원본이 암호화돼 있으면 복호화본을 diff 원본으로 쓴다(`src_transform: "xcrypt"`). 384바이트 표는 `--table`로 로컬에서만 받고, 매니페스트에는 rva·len·sha256만 적는다. 출력·로그·커밋에 표 바이트를 넣지 않는다.
  - **표 출처(확정)**: 설치기가 사용자 본인의 default.xex 복호화 이미지에서 RVA 0xB5430의 384바이트를 읽는다. sha256이 맞을 때만 쓴다.
  - 모든 해시는 SHA-256. ADD 감사: 원본과 2×BLOCK 이상 겹치는 ADD 실행이 있으면 표시한다(0이어야 함).
- `apply_patch.py`: 참조 적용기(실제 설치기는 imas2pc 공유 코어). 원본 해시 확인 → 적용 → 결과 해시 확인.
- `verify_patch.py`: 원본 ISO 해시 → 생성 → 원본 ISO를 임시 폴더에 풀고 DLC 사본을 만듦 → 적용 → game_kor·content_kor와 전수 sha256 비교 → 원본 ISO 해시.
- 무거운 작업: `gpu_run.lock`이 없고 game_kor가 2분 이상 조용할 때만, 시작 직전에 잠금을 다시 확인한다.

## PS3 (RPCS3) 패치 데이터 (gen_patch_ps3.py, 배포 전 · 빌드만)
- 사용자 결정(2026-10-25 "B"): PS3 한글 패치도 diff 패처로 배포한다. 대상은 PSN NPJB00337이다. 디스크판 BLJS10083은 매니페스트에 자리만 두고(`versions.disc = null`), 디스크 표본이 생기면 채운다.
- diff 원본(순정 참조): `Desktop\rpcs3_pristine`. RPCS3 프로그램만 복사한 곳에 원본 PKG 2개를 RPCS3 설치기로 깔았다. 해시 목록은 `pristine_sha256.json`이다. 읽기 전용으로 둔다.
- 대상은 순정 설치 파일 가운데 배포 상태에서 **내용**이 바뀐 것뿐이다. 암호화 원본의 평문 사본에 불과한 파일은 제외한다. 순정에 없는 파일(백업, 도구 산출물, 낱개 폰트)은 읽지 않는다.
- 변환: `src_transform`(none|xcrypt_ps3:n, 1,152바이트 표의 n번째 384바이트 조각)으로 원본을 풀고 KDF1 diff를 적용한다. `out_transform`(none|xcrypt_ps3, `out_prefix` orig|zero)으로 원본의 키와 풋터를 써서 다시 암호화한다. 원본 바이트와 키 표는 출력에 넣지 않는다.
  - **표 출처(확정)**: 설치기가 사용자 본인이 RPCS3로 복호화한 EBOOT.elf에서 0x575698의 1,152바이트를 읽는다(없으면 스캔). sha256 9678f64b…와 맞을 때만 쓰고, 캐시하지 않는다.
- **DLC 주의**: DLC 원본 해시는 개발팀이 제공한 패키지 `THE iDOLM@STER 2 ALL DLC.pkg`(PSN 판매 다운로드 아님)에서 뽑았다. 다른 경로로 받은 DLC 파일은 해시가 다를 수 있고, 그런 파일은 건너뛴다.
- 낱개 폰트(`resource\im2_font*`)는 넣지 않는다(`excluded`). 순정 PKG에 없는 파일이고 게임도 읽지 않는다. 게임이 쓰는 폰트는 initialFix.mpc와 initialTemp.mpc에 넣은 것이고, 이 두 파일은 diff로 들어간다.
- exe 문자열은 `imas2_kor_exe.yml`(RPCS3 패치, PSN PPU 해시 전용)을 통째로 싣는다. 새 값만 들어 있다.
- **RPCS3 실행 안내(테스터)**: RPCS3는 `--no-gui`로 실행하지 않는다(부팅 직후 거의 항상 멈춤). 일반(GUI) 모드로 실행하고, 부팅 직후(약 3~4초) 멈추면 1~2분 기다렸다가 다시 실행한다. 성공률은 약 50%다. 게임별 커스텀 설정은 필요 없고, 전역 LLVM 설정을 권장한다.
  - 근거(ui 부팅 시험): `--no-gui` 0/4, GUI 전역 LLVM 4/7. 멈춤 원인은 게임 그리기 스레드의 null 읽기 경합이라 설정으로는 고칠 수 없다.
